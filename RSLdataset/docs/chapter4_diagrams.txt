**Figure 4.2: Core Data Model & Relationships**
```mermaid
classDiagram
    class User {
        +String id (PK)
        +String email
        +String name
        +Integer xp
        +Integer level
        +Boolean is_admin
        +Json badges (Achievement IDs)
        +Json completed_lessons (Cached IDs)
    }

    class Unit {
        +String id (PK)
        +String title
        +String description
        +Integer order
    }

    class Lesson {
        +String id (PK)
        +String unit_id (FK)
        +String title
        +String description
        +Integer order
        +Integer xp
        +String achievement_id
    }

    class Task {
        <<Fields used depending on type>>
        +String id (PK)
        +String lesson_id (FK)
        +String type (Repeat Sign / Sign to Text / Text to Sign / Video Multiple Choice)
        +Integer order_index
        +String prompt
        +String explanation
        +String video_url
        +Json options
        +String expected_label
        +Float min_confidence
        +Boolean show_mascot
    }

    class Progress {
        +Integer id (PK)
        +String user_id (FK)
        +String lesson_id (FK)
        +String unit_id
        +DateTime completed_at
        +Integer xp_earned
        +Integer tasks_completed
        +Integer mistakes
        +Boolean is_perfect
    }

    class Achievement {
        +String id (PK)
        +String title
        +String description
        +String icon
    }

    User "1" --> "*" Progress : tracks (FK user_id)
    Progress "*" --> "1" Lesson : references (lesson_id)
    Unit "1" *-- "*" Lesson : contains
    Lesson "1" *-- "*" Task : contains (ordered list)
    User "1" .. "*" Achievement : earns (via JSON badges)
    Lesson "*" .. "0..1" Achievement : rewards (via achievement_id)
```

**Figure 4.3: Lesson Execution Flow**
```mermaid
sequenceDiagram
    participant Student
    participant UI as Frontend App
    participant API as Backend API
    participant DB as Database

    Student->>UI: Selects an unlocked Lesson
    UI->>API: GET /lessons/lesson/{id} (Header: X-User-Id)
    API->>DB: Fetch Lesson & Ordered Tasks
    DB-->>API: Lesson Data
    API-->>UI: Returns Task List
    
    loop For each Task in sequence
        UI->>Student: Render Task View (Video, Text, or Webcam)
        Student->>UI: Submits Answer / Performs Sign
        
        alt Task uses Webcam (e.g., Repeat Sign, Text to Sign)
            UI->>API: POST /sign/recognise
            API-->>UI: Predicted Sign & Confidence
        end

        UI->>UI: Validate Input (Check Target vs Predicted/Selected)
        UI-->>Student: Display Real-time Feedback (Correct/Retry)
    end
    
    UI->>API: POST /user/complete-lesson (Stats: XP, Mistakes)
    API->>DB: Save Progress & Check Achievements
    DB-->>API: Updated User Metadata
    API-->>UI: Return Summary & Unlocked Badges
    UI-->>Student: Display Level-up & Results Screen
```

**Figure 4.4: Webcam Sign Task Inference Flow**
```mermaid
sequenceDiagram
    participant Student
    participant UI as Camera Interface
    participant MP as MediaPipe (Client)
    participant API as Backend API
    participant AI as LSTM Inference Module
    
    Student->>UI: Start webcam sign task (Repeat Sign / Text to Sign)
    UI->>MP: Stream Live Video Frames
    
    loop Real-time Extraction (~30fps)
        MP->>MP: Detect Hands, Pose, Face
        MP-->>UI: Normalized Landmark Coordinates
    end
    
    UI->>UI: Buffer Sequence (e.g., 90 frames)
    UI->>API: POST /sign/recognise (JSON Landmarks)
    API->>AI: Process Features & Execute Model
    AI-->>API: Predicted Sign String & Confidence
    API-->>UI: Return Prediction Result
    
    alt Prediction matches Target Sign AND Confidence > Threshold
        UI-->>Student: Success Feedback & Move to Next Task
    else
        UI-->>Student: Soft Retry Prompt (Try Again)
    end
```
